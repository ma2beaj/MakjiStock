## 읽는 순서

전체 구조에서 시작해 손님이 쓰는 기능, 자동 작업, 세부 규칙 순으로 내려갑니다.

1. **전체 그림** — A1 → A2 → E1
2. **손님이 쓰는 기능** — F1 → S1 → S5 · F4 → S6 · F5
3. **매일 도는 자동 작업** — S2 → S3 → S4 → F2 → F3
4. **데이터 관리** — E2 → E3
5. **코드와 운영자 작업** — A3 → S7 → S8 → S9
6. **앞으로 만들 기능** — 05 → 06

## 기존 자료와의 관계

- `assets/diagrams/시스템 아키텍처.pdf`는 발표용 요약본입니다. 전체 흐름은 맞지만 아래 내용은 A1·A2가 더 정확합니다.
  - 공개 API인 `/api/predictions/instant`도 Cafe24에 할인코드를 씁니다.
  - Cafe24 옵션가(`variants`) 조회·수정이 빠져 있습니다.
  - `CAFE24_WRITES_ENABLED`는 환경변수가 아니라 `NODE_ENV`와 `CAFE24_ALLOW_LOCAL_WRITES`로 계산합니다.
  - `SHOP_TARGET`은 구매 이동 주소만 바꾸고, 가격 반영과 쿠폰 발급은 항상 `CAFE24_MALL_ID` 몰로 갑니다.
  - `events` 테이블은 아직 쓰지 않습니다.
- PRD와 로직구조 명세 안의 텍스트 다이어그램 중 현재 코드와 다른 곳에는 "현행 구현과 다름" 안내와 이 폴더의 링크를 달았습니다. 원문은 결정 기록이라 그대로 두었습니다.
